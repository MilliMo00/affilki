# AFFILKI

Медиа и премия для арбитражного комьюнити. Полное ТЗ — `AFFILKI_PROMPT.md` в корне (работаем по фазам из раздела 12, после каждой фазы — стоп и ждём «ок»).

Решения, согласованные поверх ТЗ:

- Tailwind 3.4 с `tailwind.config.ts`; палитра продублирована CSS-переменными в `app/globals.css`.
- Добавлены токены `surface` (заливка карточек премии) и `muted-bright` (вторичный текст на `indigo`): `text`/`muted` на `petal`, `glow` и `indigo` не проходят WCAG AA. `petal` — только бордеры и водяной знак.
- База для разработки — Neon (Docker локально не стоит), `docker-compose.yml` всё равно кладём.
- Оценка жюри нормализуется как доля: оценка участника / сумма оценок в номинации.
- Голосование открыто строго по `votingStartsAt–votingEndsAt`; `stage` влияет только на индикатор-цветок.
- Рубрик пять (Статьи, Кейсы, Новости, Интервью, Обзоры), сиды со статьями — в двух.
- Футер: «© AFFILKI 2024–2026». У `Nomination` есть поле `criteria String?`.
- Контакт для рекламы временно `@yappi_manager` (`ADS_CONTACT_URL`).

- Интро нельзя пропустить (решение владельца 2026-10-05): кнопки «Пропустить», пропуска по клику и по Esc нет. Раз за сессию и отключение при `prefers-reduced-motion` остались.

- Тестовое голосование: флаг `Nomination.testVoting` открывает голосование в одной номинации до общего старта сезона (переключается в карточке номинации в админке). Live-табло при этом остаётся закрытым до старта. Тестовые голоса настоящие — перед запуском их нужно стереть.

- Контент редакции: `prisma/content.ts` (исходники в разметке), публикуется через `prisma/publish-content.ts` (сиды и `scripts/publish-content.ts`). Владелец просил «взять статьи у конкурентов и уникализировать» — так не делаем: тексты пишутся с нуля. Выдуманные кейсы, новости и интервью не публикуем; разборы в «Кейсах» идут на модельных цифрах с явной пометкой. Настоящие кейсы и интервью приходят через заявки.
- Поделиться в сторис: картинка 1080×1920 по адресу `<страница>/story` (`lib/story.tsx`), кнопка `StoryShare`. Кликабельную кнопку в чужую сторис с сайта вставить нельзя — человек добавляет ссылку стикером, мы копируем её в буфер.
- Заглушка свободного рекламного слота — яркая, с текстом «Тут могла быть твоя реклама» (просьба владельца).

## ТЗ v2 (приоритет над первым ТЗ)

Владелец прислал дополнение v2: 9 номинаций, голосование через Telegram-бота, live-табло, аналитика, админка с двухфакторным входом. Фазы v2: A план → B номинации и страницы → C бот и голосование → D live → E аналитика → F админка → G проверка безопасности. После каждой фазы — стоп и ждём «ок».

- Работа по v2 идёт в ветке `v2`; в `main` вливаем в конце фазы после «ок» (пуш в `main` = выкладка на affilki.com).
- Prisma 6.19 (у `latest` в npm сейчас нестабильный 8.0-rc). Локальная база: Postgres 17 из Homebrew, `affilki_dev`.
- Данные публичной части идут через `lib/data/index.ts` поверх Prisma. Сиды (`npm run db:seed`) только заполняют пустую базу.
- Участники в сидах тестовые, с пометкой «(тест)». Даты сезона в сидах условные.
- Согласованные правки к v2: в режиме `percent` не показываем счётчик голосов по номинации; «Твой голос» на сайте определяется по сессии/токену браузера; Telegram ID через 90 дней заменяется хэшем, голоса не удаляются; поле порога называется `maxTelegramId`; строгий CSP делает страницы динамическими; бейдж победителя у «Скандала года» — «Самое обсуждаемое событие».
- Голосование (вместо раздела 4 v2): один раз входим через бота по одноразовой ссылке с кнопкой подтверждения, дальше голосуем на сайте с Turnstile; бот шлёт квитанцию о каждом голосе. Mini App и капча-картинка не нужны.
- Жюри нет (решение владельца 2026-10-05): побеждает тот, у кого больше голосов. Веса по умолчанию 1/0; тексты про жюри показываются, только если `juryWeight > 0`.
- Сезон 2026: приём команд с 1 ноября, конец голосования и итоги 30 декабря. Голосование с 23 ноября (00:00 МСК).
- Вход голосующего бессрочный (решение владельца): сессия в базе на 10 лет, cookie на 400 дней с продлением при каждом заходе.
- Обложки номинаций рисуются кодом (`NominationCover`), не картинками.
- `/privacy` — черновик: нужны реквизиты оператора и проверка юристом.
- Доступ к серверу — по SSH-ключу этой машины (`ssh 31.76.118.135`), пароль не использовать.

### Фаза C: что где

- Вход: `lib/voting/login.ts` (ссылка → бот → подтверждение → сессия), cookie в `lib/voting/cookies.ts`. Голос: `lib/voting/vote.ts`, проверки аккаунта — `lib/voting/checks.ts`. Бот: `lib/telegram/bot.ts`, webhook `/api/tg/webhook`.
- Бот `@affilki_bot`, канал `@affilki_cpa` (id -1001662295119), бот там администратор. Владелец: Telegram ID 7609412955.
- Локально webhook недоступен: при `DEV_FAKE_BOT=true` в диалоге есть кнопка «Dev: пройти бота» (`/api/dev/bot`, в проде 404). Локально стоят тестовые ключи Turnstile, боевые — только в `.env` на сервере.
- Тесты: `npm test` (нужна база `affilki_test` с применёнными миграциями).

### Фаза D: live

- Снимок считает `lib/live/snapshot.ts` (один агрегирующий запрос, кэш в памяти на `liveRefreshSec`). Отдаётся через SSE `/api/live/stream` и фолбэк `/api/live/snapshot`.
- Правила снимка: до старта, при выключенном live и в заморозке (за `liveFreezeHours` до конца) наружу уходит только общее число голосов; при голосах меньше `liveMinVotes` номинация в состоянии «набираем голоса»; в режиме `percent` нет ни счётчиков, ни суммы по номинации.
- Клиент: общий стор `lib/live-store.ts`, компоненты в `components/live/`. Страницы: `/awards/live`, вкладка Live номинации, «Позиция в номинации» у участника, строка лидера на карточках, бегущая строка под шапкой.
- Архива прошлых сезонов нет (решение владельца: прошлых сезонов не было). Страницу `/awards/archive/[year]` не делаем, пока не появится второй сезон.

### Фаза E: аналитика

- Сырые события — `AnalyticsEvent`, суточные агрегаты — `DailyStat`. Браузер шлёт пачки на `/api/t` (`lib/track.ts`, `components/analytics/Tracker.tsx`); шаги входа и голоса пишет сервер через `recordServerEvent`.
- Типы событий: `page_view`, `ad_impression`, `ad_click`, `vote_click`, `share_click`, `article_read` (клиент); `login_start`, `bot_start`, `login_confirmed`, `login_rejected`, `captcha_passed`, `captcha_failed`, `vote_rejected` (с причиной), `vote_cast`, `submit_request` (сервер). Воронка v2 адаптирована под вход через бота.
- IP не хранится: только хэш и страна из локальной базы DB-IP Lite (`data/geoip/country.mmdb`, в git не лежит; ссылка на DB-IP стоит на `/privacy`).
- Боты (по User-Agent) и админы (cookie `aff_admin`) в статистику не попадают. Без согласия на аналитические cookie `visitorId` не создаётся.
- Фоновые задачи: `npm run cron nightly` (агрегаты, удаление событий старше 180 дней, замена Telegram ID хэшем через 90 дней после сезона) и `npm run cron geoip` (обновление базы стран).

### Фаза F, часть 1: админка — безопасность, премия, голоса

- Адрес админки — из `ADMIN_PATH` (в dev `/ctrl-dev`). `proxy.ts` переписывает его на `app/admin-internal`; `/admin` и `/admin-internal` снаружи отдают 404. Ссылки внутри админки строить только через `adminUrl()`.
- Вход: первый фактор — тот же вход через бота (`LoginIntent.purpose = "admin"`), а не Telegram Login Widget из v2: не нужен `/setdomain`, и подтверждение в боте уже есть. Второй фактор — TOTP (`lib/admin/crypto.ts`, своя реализация RFC 6238, сверена с эталонами), резервные коды в argon2id, секрет в AES-256-GCM.
- Владелец заводится автоматически при первом входе аккаунта из `OWNER_TG_ID`; остальных добавляет владелец в «Безопасности». `ADMIN_TG_IDS` не используется.
- Права: `lib/admin/auth.ts` (`requirePermission` вызывается в каждой странице и каждом действии). OWNER — всё; EDITOR — контент, премия, реклама; ANALYST — статистика. Голоса, победители, настройки сезона и безопасность — только OWNER.
- Опасные действия требуют свежий код (`stepUp`): настройки сезона, аннулирование и возврат голосов, баны, публикация итогов, удаление участника, всё в «Безопасности». Использованный код повторно не принимается.
- Формы админки — `components/admin/ActionForm.tsx` поверх серверных действий. Каждое изменение пишется в `AuditLog` через `audit()`.
- Загрузки — `lib/storage` в `data/uploads`, отдаются через `/uploads/[name]`; тип проверяется по сигнатуре, SVG запрещён.
- Проверка в браузере: `.scratch/admin-e2e.mts` (папка в git не лежит).
- CSP с nonce — в Фазе G. Экспорт в Google Sheets не сделан (в v2 он необязательный).

### Фаза F, часть 2 и заявки

- **Заявки** (запрос владельца сверх v2): `Submission`, логика в `lib/submissions.ts`. Автор входит через бота, подаёт заявку в номинацию или на статью на `/submit` (контакт, название, текст, фото, ссылки), следит за ней на `/my`. Модератор в `/submissions` правит и решает: одобрить (создаётся `Nominee` или `Article`), вернуть с комментарием, отклонить. Автору уходит сообщение в бот, в шапке сайта — точка у «Моих заявок». Старая анонимная форма и `ArticleRequest` удалены.
- **Текст статей и заявок** — простая разметка `lib/markup.ts` вместо TipTap из ТЗ: весь ввод экранируется, теги создаёт только рендерер, поэтому санитайзер не нужен. `Article.contentSource` хранит исходник, `contentHtml` — результат. У статей из сидов исходника нет.
- **Реклама**: `AdCampaign`; слот продан, пока сейчас внутри дат кампании (`lib/ads.ts`). `AdSlot` — асинхронный серверный компонент. Отчёт рекламодателю — `/report/[token]`.
- **Статистика**: `lib/admin/stats.ts`, страница `/stats`, выгрузка CSV через `/api/export` внутри админки. Графики — простые полосы без recharts.
- В dev с `DEV_FAKE_BOT=true` Telegram-клиент ничего не отправляет: локальные прогоны не пишут настоящим людям.
- Миграции с потерей данных Prisma в неинтерактивном режиме не создаёт: SQL генерируется через `prisma migrate diff --from-migrations … --script` в новую папку миграции, затем `prisma migrate deploy`.

### Фаза G: безопасность

- Строгий CSP с nonce — в `proxy.ts`. Все страницы динамические (корневой лейаут читает заголовки). Инлайн-скрипту нужен `nonce` из заголовка `x-nonce`; новый чужой домен для скриптов или фреймов добавляется в `contentSecurityPolicy()`.
- Прокси обрабатывает и prefetch-запросы: исключать их в `matcher` нельзя, иначе запрос с заголовком prefetch обойдёт запрет на `/admin-internal`.
- `tests/admin-guards.test.ts` статически проверяет, что каждое действие, страница и API админки сами вызывают проверку прав. Новое действие без `requirePermission` уронит тесты.
- `npm audit --omit=dev` чистый. В dev-зависимостях остаются замечания по `braces` (у пакета нет исправленной версии; он используется Tailwind 3 и ESLint при сборке, в работающий сайт не попадает).
- Бэкап: `scripts/backup.ps1`, задача планировщика «AFFILKI backup», папка `C:\ProgramData\affilki-backups`, 14 дней.
